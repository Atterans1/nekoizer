# Conflicts and ambiguities in the spec, and how each is resolved

Rule applied everywhere: the explicit defaults win (block 220 ms, SOLA overlap 45 ms, steps 10, CFG 0.65, left context 2.0 s), then quality first. Anything not stated by the spec is a choice made here and is marked "choice". Measured latency is reported as measured.

## Conflicts
R1. Seed-VC xlsr-tiny vs "--f0-condition True". Evidence: the seed-uvit-tat-xlsr-tiny config has f0_condition: false in length_regulator and DiT, and Seed-VC's own real-time GUI calls it with f0=None. Direct check of the downloaded checkpoint (DiT_uvit_tat_xlsr_ema.pth, 2026-11-17): 191 tensors in 4 modules (cfm, style_encoder, vq, length_regulator), zero keys containing "f0", so the model has no F0 embedding weights at all; --f0-condition True cannot be applied to it even in principle. The F0-conditioned checkpoint is a different model (seed-uvit-whisper-base, 44.1 kHz, 200M, singing). It is not real time on a 4 GB RTX 3050, and its 44.1 kHz / Whisper chain does not fit the 220 ms / 10-step real-time defaults. Resolution: the live engine is seed-uvit-tat-xlsr-tiny with its native f0_condition false, because the explicit real-time defaults only make sense for it. F0 is still extracted with FCPE on every block, and it drives a real WORLD analysis-synthesis stage that applies semitone pitch shift, formant shift and the F0 expander to the converted block. This is NOT model-side F0 conditioning; it is a post-conversion DSP stage and its quality cost is reported. With pitch 0, formant 0 and expander 1.0 the stage is skipped entirely (bit-exact pass-through), so default quality is the model's own. Not done: running the F0-conditioned checkpoint.
R2. "Ultra-low-latency" vs the quality defaults. Resolution: keep the defaults. Latency is measured on an actual run and reported, including whether inference keeps up with the 220 ms block on this GPU.
R3. Seed-VC's pinned requirements (torch 2.4.0, transformers 4.46.3, numpy 1.26.4) vs the working environment (torch 2.14+cu126, transformers 5.2.0). Resolution: a separate venv (.venv-seedvc, hardlink overlay of the working venv; the working venv is untouched) keeps torch 2.14. Compatibility is proven only by loading and running the models; if they do not run, stop and report.
R4. Spec paths (audio/, engine/, ui/) vs the existing project layout (flat Chatterbox files). Resolution: new packages audio/, engine/, ui/ are added inside C:/Users/jeffr/s2s-voicechanger; the legacy Chatterbox modules stay in place and are not on the new app's path.
R5. "Zero-latency" sidetone. Software cannot be zero latency. Resolution: the monitor passes the processed microphone (after HPF and compressor, before conversion) to the monitor device through its own lowest-latency stream; its buffer size and measured delay are reported. It is not the converted voice.
R6. Seed-VC v2 "optional checkpoints". Resolution: not used (hubert-bsqvae-small needs an AR model plus ASTRAL quantisation, about 150M parameters more). Reported as not obtained.

## Ambiguities (choices)
R7. Raw WASAPI "Exclusive or Low-Latency Shared": try Exclusive first (bypasses audio enhancements by construction); if the device refuses, fall back to Low-Latency Shared. The mode actually in use is shown in telemetry and the UI. If the shared fallback cannot request the raw stream option through the available audio library, the report says enhancement bypass is not guaranteed in that mode.
R8. 80 Hz high-pass: 2nd-order Butterworth, applied sample-continuously (filter state kept across blocks).
R9. Compressor: soft knee 6 dB, threshold -20 dBFS, ratio 2.5:1 (spec), attack 8 ms, release 120 ms, automatic makeup = measured average gain reduction on active speech over the last 3 s, capped at +9 dB.
R10. Silero VAD: ONNX model, 512-sample frames at 16 kHz (32 ms), speech threshold 0.5, 120 ms hang (spec). Inactive output is exact digital zeros, and no model call is made for an all-silent block.
R11. Emotion reference selection (spec says RMS energy and pitch variance, thresholds not given). Per block: rms_db of active speech relative to its running median over 30 s, and pitch_std_st = standard deviation of FCPE voiced F0 in semitones over the last 1.0 s. Rules, evaluated in order: Whisper/Soft if rms_db < median - 8 dB; Angry/Intense if rms_db > median + 6 dB and pitch_std_st > 2.5; Hyped/Laughing if pitch_std_st > 3.5; else Neutral. Minimum dwell 400 ms. Empty slots are skipped (falls back to Neutral, then to the first loaded slot). Manual mode: hotkeys Ctrl+Alt+1..4 (global, RegisterHotKey) and the UI buttons.
R12. "Blend or switch": CAMPPlus style embeddings are blended with smoothed weights (200 ms time constant); the acoustic prompt latents (different lengths per clip) cannot be averaged, so they switch to the highest-weight slot at block boundaries.
R13. Ranges not given: block size 100-500 ms (default 220); overlap 40-50 ms (given as 0.04-0.05 s, default 45); all other ranges as given by the spec.
R14. Formant shift -2.0..+2.0: unit is semitone-equivalent; the spectral envelope frequency axis is scaled by 2^(x/12) in the WORLD stage.
R15. F0 expander 0.8x-1.4x: the deviation of log-F0 from its running median (last 10 s of voiced frames of the converted voice) is multiplied by the slider value.
R16. "Dry/wet timbre mix": done in the conditioning domain. 1.0 (wet) = reference style embedding only; 0.0 (dry) = the live speaker's own CAMPPlus embedding, with linear interpolation between. It is not a time-domain signal mix, because mixing the raw mic with the converted voice would add a delay-misaligned comb-filtered copy.
R17. Auto-balancer: "approaches 85%" = exponential moving average of inference time / block time >= 0.85. Then steps drop by 2 (never below the range floor of 6) for 3.0 s, then restore; it can re-trigger. On a slower GPU it may stay throttled; the report says so.
R18. Reference prompt length: Seed-VC's documented real-time setting uses at most 3.0 s of prompt; clips up to 10 s can be recorded, but at most 3.0 s of each is used as prompt (choice: constant PROMPT_MAX_S = 3.0). Longer prompts cost inference time.
R19. Presets: the spec names three presets without values. Values (choices, changing only listed controls, defaults kept): Natural Conversational = all defaults, emotion auto. High-Energy Gaming / Ragebait = F0 expander 1.3, emotion auto. Soft / Whisper = F0 expander 0.8, emotion manual on slot 3 (Whisper/Soft).
R20. The fourth preset is cut off in the source at "Ultra-Low-". Its name and its values are unknown. It is shown as a disabled slot labelled "Ultra-Low-... (name cut off in spec)" and applies nothing. No name or values are invented.
R21. Hotkeys use Ctrl+Alt+1..4 because the spec gives none (choice).
R22. FCPE chosen over RMVPE (spec allows either): smaller, pip-installable (torchfcpe).
